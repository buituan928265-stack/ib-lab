# Правило udev и запрет модуля

На сервере резервного копирования подключён диск для архивов. В лаборатории его изображает loop-устройство с образом `/srv/backup.img`, номер устройства может меняться. Рядом подключено ещё одно устройство с образом `/srv/other.img` — его правило касаться не должно. Пользователи группы `arhiv` работают с архивным диском через постоянное имя. Кроме того, служба безопасности требует запретить на сервере USB-накопители.

**Нужно:**
1. Написать правило udev в файле `/etc/udev/rules.d/70-backup.rules`. Для блочного устройства, у которого файл-образ `/srv/backup.img`, правило:
   - создаёт ссылку `/dev/backupdisk`;
   - назначает группу `arhiv`;
   - назначает права `0660`.
   Номер устройства (`loop3`, `loop5`…) в правиле не указывайте: он меняется. Выбирайте устройство по атрибуту из sysfs.
2. Запретить модуль ядра `usb-storage` (драйвер USB-накопителей) через каталог `/etc/modprobe.d`:
   - модуль не загружается автоматически при подключении устройства;
   - его нельзя загрузить и вручную командой `modprobe usb-storage`: вместо загрузки выполняется `/bin/false`.

**Подсказка:** найдите устройство командой `losetup -j /srv/backup.img`. Атрибуты устройства покажет `udevadm info -a -n /dev/loopN`. Служба udev в лаборатории не запущена, поэтому правило проверяйте командой `udevadm test /sys/class/block/loopN`. Настройки modprobe покажет `modprobe -c`.

На настоящем сервере после правки правил выполняют `udevadm control --reload` и `udevadm trigger`.
