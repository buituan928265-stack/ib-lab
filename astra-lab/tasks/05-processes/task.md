# Разбор с процессами на сервере

Пользователи жалуются, что сервер тормозит. Дежурный оставил записку:
- кто-то из бухгалтерии запустил тяжёлую программу, она съедает процессор. Это построение годового отчёта, **прерывать его нельзя**, но остальным оно мешать не должно;
- служба синхронизации `uchet-sync` зависла, её надо остановить. При нормальной остановке она убирает за собой файл блокировки `/var/lib/uchet/sync.lock`. Если файл останется, служба больше не запустится;
- в настройки службы `uchet-agent` внесли изменения. Служба умеет перечитывать настройки по сигналу `HUP`, перезапускать её нельзя: она держит подключения пользователей.

**Нужно:**
1. Найти процесс, который больше всех нагружает процессор, и снизить ему приоритет: значение nice — не меньше 10. Процесс должен продолжить работу.
2. Остановить `uchet-sync` так, чтобы она успела убрать файл блокировки.
3. Заставить `uchet-agent` перечитать настройки, не перезапуская её (номер процесса не должен измениться). Если всё получилось, в `/var/log/uchet/agent.log` появится строка о перечитывании.

**Подсказка:** `top` (сортировка по процессору — по умолчанию, выход — `q`) или `ps aux --sort=-%cpu | head`; `renice`; `pgrep -a`, `kill` и `kill -l`. Подумайте, какой сигнал посылает `kill` без ключей и почему `kill -9` здесь плохой выбор.
