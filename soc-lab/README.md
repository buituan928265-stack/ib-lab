# Лаборатория SOC: синтетические журналы и учебный SIEM

Учебный стенд к курсу «Аналитик SOC первой линии». Вы — аналитик первой линии
в вымышленной компании LAB, смена 20.10.2026. В SIEM загружен один рабочий день:
около 5 600 событий из 10 источников. В обычной работе ~45 сотрудников спрятаны
несколько настоящих инцидентов, ложные срабатывания и «слепые зоны».

| Источник | Что внутри |
|---|---|
| logs-windows | Журнал безопасности Windows: входы 4624/4625, блокировки 4740, учётные записи и группы 4720/4728/4732 |
| logs-sysmon | Sysmon: запуск процессов (1), сетевые подключения (3), DNS-запросы (22) |
| logs-linux | Журнал SSH и sudo веб-сервера SRV-WEB-01 |
| logs-dns | DNS-сервер компании |
| logs-proxy | Прокси: кто, куда, сколько байт отправил и получил |
| logs-vpn | VPN-шлюз: подключения, MFA, страна и провайдер |
| logs-mail | Почта: отправитель, получатели, вложения, SPF/DKIM/DMARC |
| logs-zeek | Сетевой датчик Zeek: журнал соединений |
| logs-suricata | Сетевой датчик Suricata: срабатывания правил |
| logs-heartbeat | «Пульс» источников раз в 5 минут — для проверки, все ли журналы поступают |

Кроме поиска, в SIEM работает модуль **Security Analytics** с правилами Sigma: детектор
«LAB Sysmon» проверяет события Sysmon тремя учебными правилами (они же лежат в `sigma/`).

Все данные синтетические: имена, адреса и домены вымышленные. Учебный SIEM —
[OpenSearch](https://opensearch.org/) с веб-интерфейсом OpenSearch Dashboards
(открытая лицензия Apache 2.0). Навыки переносятся на другие SIEM: поиск по полям,
агрегации, временные шкалы и корреляция устроены похоже.

## Что нужно

- Docker Desktop (Windows, macOS) или Docker Engine (Linux) — как для лаборатории базового курса
  (установка описана в [../../01-osnovy-ib/lab/README.md](../../01-osnovy-ib/lab/README.md)).
- Около 4 ГБ свободной оперативной памяти и 6 ГБ места на диске.
- Браузер.

## Запуск

Откройте терминал в папке `courses/02-soc-analyst-l1/lab`:

```
docker compose up -d
```

Первый запуск занимает 5–12 минут: Docker скачивает образы SIEM (около 5 ГБ),
загружает журналы и настраивает правила Sigma. Проверить, что загрузка закончилась:

```
docker compose logs loader
```

В конце должно быть «Готово. Откройте http://127.0.0.1:5601».

## Работа

**SIEM в браузере:** http://127.0.0.1:5601 → меню ☰ → **Discover**. Источник
выбирается слева вверху, диапазон времени уже стоит на 20.10.2026, время показано
по Москве.

**Рабочее место аналитика** — терминал с заданиями, проверками и сырыми журналами:

```
docker compose exec analyst bash
```

| Команда | Что делает |
|---|---|
| `soc` | список заданий |
| `soc 01` | открыть задание и создать файл ответов |
| `nano ~/answers/01.txt` | вписать ответы |
| `soc check 01` | проверить ответы |
| `soc data` | где лежат журналы и справочники (сотрудники, активы, заявки) |
| `soc replay` | заново подать события Sysmon детектору Security Analytics (задание 14) |

Задания 01–12 разбирают отдельные темы курса (входы Windows, перебор паролей, Sysmon,
фишинг, учётные записи, утечка, Linux, VPN и MFA, здоровье источников, Zeek и Suricata).
Задание 13 — итоговый разбор смены, как в проекте урока S33. Задание 14 — правила Sigma
в Security Analytics: разбор срабатываний, узкое исключение и своё правило.

Ответ ищите сами: проверка подсказывает, где ошибка, но не раскрывает правильный ответ.

## Остановка и сброс

| Команда | Что делает |
|---|---|
| `docker compose stop` | остановить; данные и ответы сохранятся |
| `docker compose up -d` | запустить снова |
| `docker compose down -v` | удалить всё, включая загруженные журналы и ответы |

## Если что-то пошло не так

- **Страница http://127.0.0.1:5601 не открывается** — SIEM ещё запускается, подождите
  1–2 минуты. Посмотреть состояние: `docker compose ps` (у opensearch должно быть `healthy`).
- **В Discover нет событий** — проверьте диапазон времени: нужен 20.10.2026.
  Кнопка с календарём слева от диапазона → Absolute.
- **В Security Analytics → Findings пусто** — время срабатывания там — момент проверки
  детектором, а не время события, а по умолчанию показаны только последние 24 часа.
  Расширьте диапазон (Last 1 year). Если пусто и так — выполните `soc replay` в терминале
  аналитика и подождите 1–2 минуты.
- **opensearch постоянно перезапускается** — Docker не хватает памяти. В Docker Desktop:
  Settings → Resources → Memory, выделите не меньше 4 ГБ.
- **Ошибка «max virtual memory areas vm.max_map_count» на Linux** — выполните
  `sudo sysctl -w vm.max_map_count=262144`.
