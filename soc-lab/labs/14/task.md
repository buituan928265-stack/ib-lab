ЗАДАНИЕ 14. Правила Sigma в Security Analytics
==============================================
Уроки курса: S24, S25, S26

В SIEM работает модуль Security Analytics: детектор «LAB Sysmon» проверяет события Sysmon тремя учебными правилами Sigma. Разберите их срабатывания, найдите ложное и напишите своё правило.

Что сделать
-----------
Часть 1. Правила и срабатывания
1. В браузере: меню ☰ → Security Analytics → Detection rules. В фильтре Source выберите Custom —
   это три учебных правила «LAB: …». Откройте каждое и посмотрите YAML: какие поля и условия в нём.
   Те же правила лежат в терминале: ls /lab/sigma и cat /lab/sigma/*.yml
2. Security Analytics → Findings — срабатывания правил. ВАЖНО: время срабатывания — это момент, когда
   детектор проверил событие, а не время самого события. Если список пуст, расширьте диапазон
   (кнопка с календарём → Last 1 year).
3. Нажмите на номер срабатывания (Finding ID): справа откроются правило, его теги ATT&CK и само событие.
   Для каждого правила запишите, сколько у него срабатываний и на каком узле.
4. Правило «PowerShell запущен службой Windows» срабатывает несколько раз. Посмотрите командную строку
   и узел, сверьтесь с /lab/data/tickets.csv. Это атака или ложное срабатывание?

Часть 2. Узкое исключение (на бумаге, в ~/answers/14.txt)
5. Допишите в это правило фильтр, который убирает только плановую задачу резервного копирования, а не все
   запуски PowerShell от svchost.exe. Подсказка — структура Sigma:
       filter_backup:
         Computer: 'SRV-BACKUP-01'
         CommandLine|contains: 'C:\Scripts\backup\job.ps1'
       condition: selection and not filter_backup

Часть 3. Своё правило
6. Напишите правило, которое находит процессы, запущенные программой из временной папки пользователя
   (поле ParentImage содержит \AppData\Local\Temp\). Сначала предскажите, сколько событий оно найдёт:
       jq -c 'select((.process.parent.executable // "") | contains("\\AppData\\Local\\Temp\\"))' /lab/data/sysmon.ndjson
7. Создайте правило: Detection rules → Create detection rule → YAML editor. Log type: Windows.
   Возьмите за образец любое правило из /lab/sigma: обязательно укажите строку id: со своим UUID
   (например 7c1e2a10-0b5a-4c8e-9f20-2010202600aa) — без неё правило не сохранится.
8. Добавьте правило в детектор: Detectors → LAB Sysmon → Edit (раздел Detection rules) → отметьте своё правило → Update.
9. Детектор проверяет только новые события. Подайте их заново командой soc replay в терминале
   и через 1–2 минуты откройте Findings: должны появиться срабатывания вашего правила.
   (Срабатывания учебных правил при этом повторятся — это нормально.)

Как искать в SIEM
-----------------
Откройте в браузере http://127.0.0.1:5601 → меню ☰ → Discover.
Слева вверху выберите источник (logs-windows, logs-sysmon… или logs-* — все сразу).
Диапазон времени уже выставлен на 20.10.2026; время показывается по Москве.
Строка поиска понимает язык DQL:
    event.code:4625                         поле равно значению
    user.name:"a.ivanov"                    текст в кавычках — точное значение
    event.code:4625 and source.ip:203.0.113.20
    not user.name:"svc-backup"
    source.ip:"203.0.113.0/24"              адрес из подсети
Число найденных событий показано над таблицей: Results (N).
Чтобы видеть нужные поля столбцами, наведите на поле слева и нажмите «+».

Как искать в терминале (рабочее место аналитика)
------------------------------------------------
Те же события лежат в /lab/data/*.ndjson — одна строка JSON на событие, время в UTC.
    jq -c 'select(.event.code=="4625")' /lab/data/windows.ndjson | wc -l
    jq -r 'select(.event.code=="4625") | .user.name' /lab/data/windows.ndjson | sort | uniq -c | sort -rn | head
SIEM можно спросить и напрямую:  curl -s "$OPENSEARCH_URL/logs-windows/_count?q=event.code:4625" 

Время в заданиях — по Москве. Ответы — в ~/answers/14.txt, проверка — soc check 14.
