УРОК 08. Диагностика сети без шаманства
========================================

Что вы сделаете: разберёте три поломки по порядку проверок
«подключение → настройки → имя → порт → приложение» и одну исправите сами.

Полезные команды
----------------
  ip -4 addr show eth0          адрес и префикс
  ip route                      шлюз
  cat /etc/resolv.conf          какой DNS-сервер используется
  dig portal.test               ответ DNS
  nc -zv portal.test 80         открыт ли TCP-порт
  curl -i http://portal.test/   ответ приложения

Случай А. «Сайт не открывается»
-------------------------------
1. Включите поломку:  lab break dns
2. Пользователь жалуется: curl http://portal.test/ не работает.
3. Пройдите проверки по порядку и найдите, на каком этапе проблема.
4. Перед исправлением запишите, как было (cat /etc/resolv.conf), чтобы можно
   было вернуть настройку. Исправьте одну вещь и повторите проверку.
Переходите к случаям Б и В только после того, как исправите случай А:
пока имена не находятся, другие проверки тоже не сработают.

Случай Б. «Новый сервис отчётов не работает»
--------------------------------------------
Разработчики говорят, что сервис отчётов запущен на portal.test, порт 8081.
Пользователи получают ошибку. Проверьте имя, порт и ответ приложения:
     nc -zv portal.test 8081
Исправлять здесь нечего: определите этап и кому передать проблему.

Случай В. «Заказ не оформляется»
--------------------------------
     curl -i http://portal.test/order
Соединение есть, имя находится, но приложение отвечает ошибкой.
Запомните номер запроса из ответа и найдите его в журнале приложения:
     grep <номер запроса> /lab/logs/portal.log
Запишите, какой файл приложение не смогло открыть.
