# Windows-часть лаборатории (уроки 10–13)

Необязательная часть: настоящий Windows Server 2022 (ознакомительная версия,
180 дней) в роли контроллера домена `lab.test`. На нём выполняются Windows-задания
к урокам о правах, службах, журналах и Active Directory.

## Подойдёт ли ваш компьютер

| Нужно | Почему |
|---|---|
| Windows 11 с Docker Desktop или Linux с Docker | Windows запускается как виртуальная машина внутри контейнера, нужен KVM. На Windows 10 и macOS Docker Desktop KVM не даёт — там эта часть не запустится |
| ~30 ГБ свободного места | образ установки (~6 ГБ) и диск Windows |
| 4 ГБ свободной оперативной памяти | столько выделяется Windows |
| интернет при первом запуске | образ скачивается с сайта Microsoft |

Если компьютер не подходит, выполняйте задания ниже по скриншотам из материалов курса.

## Запуск

Из папки `lab`:

```
docker compose --profile windows up -d windows
```

Первый запуск долгий: 30–60 минут. Windows скачивается, устанавливается,
становится контроллером домена и перезагружается. Следить за процессом можно
в браузере: http://127.0.0.1:8006

Готово, когда на рабочем столе появился вход в систему, а через пару минут после
входа существует файл `C:\OEM\seed-done.txt`.

Вход: пользователь `LAB\labadmin`, пароль — значение `PASSWORD` в `compose.yaml`.
Удобнее подключаться программой «Подключение к удалённому рабочему столу»
(mstsc) к адресу `127.0.0.1`.

Остановить: `docker compose --profile windows stop windows`.
Удалить вместе с диском Windows: `docker compose --profile windows down -v`
(учтите: `-v` удалит и ответы в Linux-части).

## Урок 10. Права доступа

Стажёр intern.sidorov должен только читать инструкции. Есть жалоба: он смог
изменить файл.

1. Посмотрите список разрешений папки: `icacls C:\Shares\Instructions`
2. Посмотрите группы стажёра: `Get-ADPrincipalGroupMembership intern.sidorov | Select Name`
3. Проверьте фактический доступ: свойства папки → Безопасность → Дополнительно →
   «Действующие разрешения» → выберите intern.sidorov.
4. Найдите, через какую группу стажёр получил право изменения. Уберите лишнее
   так, чтобы читатели и редакторы сохранили свой доступ.
5. Повторите шаг 3 и убедитесь: чтение есть, изменения нет.

Чек-лист: найдена причина (лишняя группа), исправлено через группы, а не
персональным запретом; сделаны обе проверки — разрешённое работает, лишнее нет.

## Урок 11. Службы и процессы

1. `Get-Service | Where-Object Status -eq Running | Select -First 15`
2. Найдите службу DNS-сервера: `Get-Service DNS`. Каким процессом она работает?
   `Get-CimInstance Win32_Service -Filter "Name='DNS'" | Select Name, ProcessId, PathName`
3. Проверьте, что служба не только «работает», но и отвечает:
   `Resolve-DnsName lab.test -Server 127.0.0.1`

Чек-лист: состояние службы и ответ сервиса проверены отдельно; ни одна служба
не остановлена «на всякий случай».

## Урок 12. Журналы

1. Найдите события входа m.petrova:
   ```
   Get-WinEvent -FilterHashtable @{LogName='Security'; Id=4624,4625} |
     Where-Object { $_.Message -match 'm.petrova' } |
     Select TimeCreated, Id -First 10
   ```
   4625 — неудачный вход, 4624 — успешный.
2. Составьте хронологию: время (с часовым поясом), событие, учётная запись, результат.
3. Ответьте: доказывают ли эти события взлом? Что ещё нужно проверить?

Чек-лист: в хронологии указан часовой пояс; наблюдения и гипотезы записаны
отдельно; нет вывода «это точно атака».

## Урок 13. Active Directory и групповые политики

1. `Get-ADUser -Filter * -SearchBase "OU=Former,DC=lab,DC=test" -Properties Enabled, MemberOf`
   Учётная запись o.leaving отключена. В каких группах она всё ещё состоит?
   Составьте список того, что нужно проверить при уходе сотрудника.
2. Политика: `Get-GPInheritance "OU=Interns,DC=lab,DC=test"` — какие политики
   действуют на стажёров? Отчёт о политике:
   `Get-GPOReport -Name Lab-Interns-ScreenLock -ReportType Html -Path C:\gpo.html`,
   затем откройте файл.
3. Создайте свою безобидную политику (например, обои рабочего стола) и привяжите
   её только к OU Interns. Проверьте командой из шага 2, что на Staff она не попала.

Чек-лист: понятно, что отключение учётной записи не убирает её из групп и не
закрывает уже открытые сеансы; новая политика привязана только к нужному OU.
